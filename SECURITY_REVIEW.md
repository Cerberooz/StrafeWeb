# Store security review

Reviewed SSR rendering, external catalog ingestion, markup parsing, customer selection, checkout, points reads and server configuration.

## Implemented protections

- Bot announcements use a server-only bot token with a fixed Discord HTTPS API origin and validated channel/message IDs. The Gateway client requests no intents and logs only fixed event names. It closes on process shutdown. Grant only View Channel, Send Messages and Embed Links. Bot identity is managed in Discord; the webapp sends no username/avatar override. Saved receipts retain the original bot channel for edits without storing credentials. Legacy sender receipts remain duplicate markers and are not edited.

- `POST /webhooks/paynow` verifies PayNow's HMAC-SHA256/base64 signature over raw bytes and rejects timestamps outside five minutes, using constant-time comparison. The route precedes browser CSRF/session middleware and has its own body/rate limits. Only completed orders from the configured store can trigger a Discord notification; outbound URLs must match Discord's HTTPS webhook endpoint. Messages use escaped player/product text and no billing details. Discord-link events use the main signing secret by default, or an optional separate link-webhook secret; they require matching nested store/order IDs and a valid Discord user ID, and can save that ID or edit a previously confirmed purchase notification. Only the verified linked user is allowed to be mentioned; role/everyone mentions are disabled. Secrets and upstream error bodies are excluded from logs. Order receipts and linked IDs persist in a Docker volume; events for one order are serialized to prevent concurrent duplicate posts.

- All untrusted text and URL attributes use EJS's HTML escaping. Raw HTML rendering is limited to the output of `sanitize-html`, using the exact TABLE_MARKUP allowlist. No scripts, SVG, frames, forms, handlers, styles or arbitrary attributes survive. Description/perk images must use HTTPS on an exact `RANK_IMAGE_HOSTS` hostname without credentials or explicit ports; dimensions must be numeric. Unknown hosts are removed, with no wildcard or subdomain matching. Labels, section titles, rank names, prefixes and leaderboard names remain text.
- Content Security Policy allows same-origin scripts/styles, denies frames/objects and restricts form posts to the same origin. Image sources are limited to the same origin, approved markup hosts, and specific artwork origins from trusted provider catalog fields or the configured hero image. There is no blanket HTTPS image permission. Catalog artwork handling remains separate from rich HTML sanitization. Helmet sets additional browser security headers. External legal/community links use `noopener noreferrer`.
- Points and PayNow API keys are server environment values; browser pages have no API-key fields or requests to the points service. Use an isolated leaderboards:read key for this SSR application. A browser route cannot forward arbitrary endpoints or execute a points write.
- Solo portraits use a server-only bulk account appearance read with the existing leaderboards:read key. UUIDs come from leaderboard subject IDs, never a browser-selected account query. The SSR response carries only a PNG URL: no texture signatures, Discord identities, access tokens or account writes. Portrait URLs must match the configured public API origin and exact `/v1/accounts/portraits/{texture hash}/{classic|slim}.png` path; the texture must use `https://textures.minecraft.net/texture/{same hash}`. Credentials, query strings, fragments and other paths are rejected before rendering. The tiers response adds only that configured origin to CSP when it actually includes portraits. Images suppress referrers and use a local SVG fallback with no inline event handlers.
- PayNow customer tokens live in signed, HttpOnly, SameSite=Lax cookies with Secure enabled in production. POSTs require a session-bound HMAC CSRF token and exact configured Origin. A username chosen for delivery is intentionally not proof of ownership and does not authenticate a user to the points system.
- Checkout receives no browser price. Product, billing mode, stock, custom-variable options and game server are checked against a fresh PayNow response. The provider performs tax/pricing validation. Redirects are restricted to HTTPS PayNow hosts. Account identity is included in session-scoped auth coalescing and the checkout retry key, preventing duplicate first auths and reuse across account switches.
- Signing and checkout have separate request limits. General page requests are rate limited. Proxy trust accepts only an integer hop count from 0 to 10. Upstream requests have timeouts, redirect rejection and bounded responses; caches, the two-minute checkout retry map and the two-minute customer-auth map have bounded entries. Non-success upstream response bodies are cancelled before throwing; provider error content is not read or exposed to visitors/logs. Provider errors return generic messages without tokens/stack traces.
- Production startup rejects short/missing cookie secrets, non-HTTPS public origins and non-HTTPS remote points endpoints. Localhost points traffic is allowed for independently running apps behind the same host.

## Remaining operational risks

- The Discord notification receipt directory must be mounted persistently and writable by the runtime user; operate one webapp replica with this file store. If Discord accepts a post but its response times out or the process stops before recording success, a provider retry may post a duplicate. Notification failures return 503 for PayNow's retries. These messages are notifications, not fulfillment signals.

- Approved description image hosts still receive visitor IP addresses. Keep `RANK_IMAGE_HOSTS` restricted to hosts your administrators trust; the default is empty and disables embedded description images. Changing the list requires an app restart. Other previously accepted description image hosts will be removed until explicitly approved. Top-level artwork from the trusted PayNow API and the configured hero image also reaches its own hosting provider; only use trusted provider/admin artwork.
- The configured public account API receives visitor IP addresses when portrait PNGs load. It is the only added image host; browsers do not contact Mojang or third-party avatar services for these portraits. Appearance UUID reads and PNG URLs are public display data, so the API should retain its own request limits and portrait cache bounds. SSR limits its appearance cache to 2048 entries and 16 concurrent bulk batches; API outages preserve prior cached skins until eviction or process restart. Appearance changes propagate after the short cache TTL and apply to historical rows as well as the current season.
- PayNow's direct Minecraft username flow accepts an account name for delivery. It must never be repurposed as verified Minecraft identity for privileged store/points account actions.
- Payment completion redirects and browser notifications are not trusted fulfillment signals. This app deliberately grants no points, ranks or custom entitlements on those routes; PayNow's configured delivery is authoritative. Future custom fulfillment needs signature validation and durable event-ID replay protection.
- Checkout coalescing and rate limits are process local. Run a shared limiter/cache or edge rate limits for multiple replicas. A replay can create an extra payment session after TTL/restart; it cannot grant an entitlement locally. Valid leaderboard pages are public, so a high-volume sweep of distinct valid pages can churn the 256-entry cache and consume read-only API quota; keep the API key read-only and apply edge limits if the upstream quota is restrictive.
- Competitive tier thresholds are configurable on the SSR server and default to values inferred from the mockup (2600/2250 boundaries). They are display rules, not API-owned truth; keep them aligned with the server's actual competitive rules. API-provided tier metadata takes precedence.
- Figma contexts and original artwork were retrieved through the Figma connector, then stored locally. Live provider credentials were unavailable; payment behavior and authenticated API reads remain to be verified after configuration. No real purchase was made.

Production dependency audit: `pnpm audit --prod` returned **No known vulnerabilities found** at review time.
